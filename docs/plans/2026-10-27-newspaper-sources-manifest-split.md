## Wave 1

### t1 — http.call resolves a header `<word> grant:<NAME>` (generic)

- instruction: Change only HttpCallPort.`_header_value` in `culture_rules`/node/actions/http.py: accept exactly one word of \[A-Za-z\]\[A-Za-z0-9.`_`-\]\*, one space, then a grant: reference; resolve the reference with resolve(..., redactor=redactor) and return the word, a space and the value. Update the module docstring's headers paragraph. One assert per condition in tests (CI's Sonar gate).
- covers: c25, h1, h2
- acceptance:
  - tests/node/`test_http_grant_scheme.py`: a header `Bearer grant:<NAME>` on the actor policy or the step is sent as `Bearer <value>` (fake secret runner), and the value never appears in the step's output
  - Values with grant: anywhere else (`x grant:A grant:B`, two words before the reference, a trailing space) are sent unchanged, never half-resolved; a bare `grant:<NAME>` behaves exactly as before (existing http.call tests pass unchanged)
  - An unresolvable reference after a word fails `secret_unresolved` naming the header, as a bare one does

### t3 — Generic sections builtin: split an EPUB, HTML or Markdown document at a configured heading

- instruction: The builtin is generic: no newspaper, library or field name in code; every rule is config or input (c21: links are the hrefs the section cites). Pick a generic builtin name (e.g. document.sections) and keep run-state outputs to the section list and counts. Standard library only (html.parser, zipfile). Do not touch runner.py, describe.py or the editor (t4 wires them).
- covers: c27, h5, h6, h16, c6, h23, c8, h7, c13, h25, c12, h11
- acceptance:
  - New `culture_rules`/node/actions/sections.py (port + pure function) and tests/node/`test_sections.py`: input `content_base64` (EPUB), html, markdown, or `content_path` under `content_root` (a path outside the root or through a symlink fails `path_refused`); config `split_on` (an h1-h6 tag, or a Markdown heading level), paragraphs, `max_chars`, `require_links`, fields (output-name renames)
  - Each section: the heading text, its http(s) links in order without duplicates (hrefs in EPUB/HTML; \[label\](url) and bare URLs in Markdown), and an excerpt of the first N paragraphs as text (block tags to paragraph breaks, entities unescaped, whitespace collapsed), cut at a word boundary to `max_chars`; `require_links` drops sections with no link
  - Real-issue test: render an issue with newspaper.render (some sections with results, one with none), run sections on its EPUB with `split_on` h2, paragraphs 1, `max_chars` 300, `require_links`, fields {heading: `article_title`, links: `source_urls`, excerpt: excerpt}; entry count = sections with results, titles = h2 texts, each entry's links are only its section's
  - Contract test: culture-library's extraction, chunking (1000 chars on blank lines) and matching (first 120 normalised chars inside one chunk) rules, copied as test fixtures with a citation, match every entry of that manifest; the manifest passes a copy of `validate_manifest`'s rules
  - Two different configs on the same EPUB give two different outputs; the newspaper byte pins (tests/node/`test_epub_bytes_pinned.py`) still pass

## Wave 2

### t2 — http.call `save_to`: stream the response body to a file under a root the actor lists (generic)

- instruction: Extend `culture_rules`/node/actions/http.py only (t1 lands first in the same file). Reuse `attachment_fetch`'s streaming-to-temp-then-rename pattern and its `O_NOFOLLOW`/realpath checks; do not import `attachment_fetch`'s Discord defaults. `save_to` is a step param (an absolute path); the policy decides what is allowed. Keep everything else in http.call unchanged.
- covers: c26, h3, h4, h17
- acceptance:
  - tests/node/`test_http_save_to.py`: with `save_to` set to a root in the actor's params.http.`save_roots`, a 2xx body is written to `<root>/<sha256>.<ext>` (atomic rename from a temp file in the root) and the outputs are status, path, sha256, size and `content_type`; no output holds the body
  - `save_to` outside `save_roots`, a symlinked root, an existing symlink at the target name, or no `save_roots` fails `path_refused` before any request is sent
  - The extension comes from the response Content-Type mapped onto {application/epub+zip: epub, application/pdf: pdf, text/markdown: md, application/json: json, text/plain: txt} (parameters such as charset ignored); any other type fails `unsupported_type` and writes nothing
  - A body over the cap (`save_max_bytes`, default 50 MiB, set on the policy) fails `too_large` and leaves no file or temp file behind; a 4xx/5xx is not saved and fails as http.call does today

### t7 — `for_each` outcomes: each iteration's status, errors and collected outputs as a loop output (generic engine)

- instruction: Change `culture_rules`/engine/runs.py (`_progress_loop` records each iteration's body states into the outcome; `_loop_outputs` emits outcomes when the port is declared) and `culture_rules`/model/validate.py (check collect). Keep the outcome small: scalars and error messages only, never a body step's whole outputs. Then update the t5 flow test and the docs page. Test-first: see the new tests fail before the engine change.
- covers: h13, c10
- acceptance:
  - tests/engine/`test_for_each_outcomes.py`: a `for_each` loop that declares an output port named outcomes gets one entry per item, in order: {index, item, status, errors}; status is succeeded when every body step succeeded, skipped when any body step was skipped (by `on_error` skip or `input_missing`), and errors maps each such step id to its error message
  - config.collect (`{name: "<body step>.<output>"}`) copies those body-step outputs into each entry (null when the step did not output it); an unknown step id or a malformed path is refused by validate before the run starts
  - A `for_each` loop without an outcomes port behaves exactly as before (existing loop tests pass unchanged); `retry_until` loops are unchanged; a failed body step still fails the loop
  - tests/rules/`test_sources_manifest_flow.py`'s backfill asserts on the run's outputs: the outcomes list holds every id given, pushed ones with their entry count via collect, the skipped one with its error; docs/operations/sources-manifest.md shows outcomes and collect in the backfill example; the engine docstring and CHANGELOG (0.36.0) describe the port

## End state

### Announcement

- Every daily newspaper issue in culture-library carries a sources manifest (each article's title, the URLs it links and a verbatim excerpt), pushed right after the issue, and the issues already in the library have one too

### After state

- Each new newspaper issue in culture-library has a sources manifest within the same run that pushed it, the earlier issues have one from the backfill (skips listed), and newspaper evals can be generated for every issue

### Success signals

- culture-library's newspaper eval generator (generate_newspaper_set) matches every manifest entry of a fresh issue to at least one chunk, with unmatched = 0
- After the backfill, GET /api/library/{id}/sources answers a manifest for every newspaper item except the listed skips
