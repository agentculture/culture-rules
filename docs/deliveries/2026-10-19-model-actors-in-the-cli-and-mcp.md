# Delivery Summary — Model actors in the CLI and MCP

plan: `model-actors-in-the-cli-and-mcp` · run: `complete` · date: `2026-10-19`
baseline: `devague summary skeleton`

## Intent

> culture-rules enrols each local model as its own actor from the gateways' /v1/models, lists where an actor is used, repoints a workflow from one actor to another and refuses to disable an actor still in use: one CLI verb and one MCP tool each, dry-run by default

After: Three verb calls replace the script: actors enrol-models makes or updates one agent actor per matching model, workflows repoint-actor moves a workflow's steps to it with `expected_revision`, and actors disable refuses while an enabled workflow still names the actor; actors references shows where an actor is used

## Mid-work Decisions

- `d1` — references.py lives in `culture_rules`/model/references.py (test in tests/model/`test_references.py`), not `culture_rules`/actors/ — tests/`test_boundaries.py` keeps engine, node and actors from reading workflow/step notes; the c14 notes-mention warning reads them, and `culture_rules`/model already holds the workflow-text readers (describe.py, paragraph.py); operator approved 2026-10-19
- `d2` — t6 changed one existing fixture: `_pooled_store`() in tests/node/`test_llm_complete.py` gives the fixer actor its own model (fixer-model); no assertion changed — the fixture seeded two enabled endpoint actors on model qwen-test, which the approved one-model rule (c26) now refuses at runtime; operator approved 2026-10-19
- `d3` — enrol-models responses list actor ids and actions (create/update), not revisions — actors carry no revision field in the store; only workflows do (repoint-actor returns the new workflow revision). Adding actor revisions is a store/model change beyond this spec. Operator approved.
- `d4` — `model_gateways` is a list of 'machine=URL' strings, not a machine->URL object — variables hold only a JSON scalar or a list of scalars (`culture_rules`/model/variable.py `validate_variable_value`); objects are refused. Operator chose the list form (d3 a) over extending variables.
- `d5` — the actor guards also cover restore and import (`model_taken`) and delete (`actor_in_use`, --force); repoint checks the target can run the repointed actions (llm.complete needs an endpoint actor; other kinds must match the action's actor kind); the run-time `model_taken` check refuses only actors newer than the holder (`created_at`, then id), so the oldest keeps serving — code review of PR #72: restore/import could create a second holder, delete removed an in-use actor that disable refused, repoint accepted a target that fails at run time, and the symmetric run-time check stopped every actor on a shared model; approved by the operator 2026-10-20
- `d6` — the run-time `model_taken` winner is the holder with the lowest actor id, not the oldest by `created_at` (d5): actor documents carry no creation time — d5 named `created_at`, but actor documents store no `created_at` (only `updated_at`, which changes on every save); the lowest id is deterministic, so every node picks the same winner
- `d7` — t12's enrol-models ran with --match cortex-spark2, not --match 'cortex-\*': it enrolled cortex-spark2 only; no cortex-spark lane actor exists — the gateway on spark served no cortex-spark model (spark is testing and evaluating models); operator 2026-10-22: 'Go for cortex-spark2 pure'. Approved at the time; this record is filed late, at closeout
- `d8` — t12 added a fifth live write: workflows update daily-newspaper --expected-revision 2 rewrote only the summarise step's notes to name cortex-spark2 (revision 3), from a scripted JSON body — repoint-actor never edits notes (c14), so the summarise notes still named newspaper-llm; operator 2026-10-22: 'Please do'. Approved at the time; this record is filed late, at closeout
